# 🏢 Enterprise IT Asset & Lifecycle Management System

An advanced, secure, AI-powered enterprise platform designed to track, audit, and orchestrate hardware and software assets across global infrastructure. Built using a robust microservices-ready layered architecture, the platform features precise Role-Based Access Control (RBAC), real-time event streaming, and an intelligent RAG-driven AI agent workflow to automate IT helpdesk operations.

---

## 📖 The Engineering Story: Architectural Challenges & Decisions

When scaling an enterprise IT management platform, traditional CRUD architectures fail to meet real-world operational demands. This project was engineered from the ground up to solve three critical enterprise bottlenecks: **UI Performance under high load**, **Secure Data Governance**, and **Asynchronous Automated Operations**.

### 1. High-Density UI Performance (Frontend Orchestration)
Managing thousands of infrastructure assets simultaneously causes severe DOM degradation if not handled correctly. To solve this, the frontend utilizes **React Window** for virtual scroll list rendering, ensuring only visible elements consume DOM nodes. State management is split carefully: **Redux** governs global, client-side UI states, while **React Query (TanStack)** handles server-state caching, background data synchronization, and automated re-fetching. 
To eliminate unnecessary component re-renders during high-frequency live updates, strict memoization primitives (**React.memo**, **useMemo**, and **useCallback**) shield complex sub-trees, keeping operational overhead near zero.

### 2. Zero-Trust Security & Sealed Storage (Backend Defense)
Security cannot rely on client-side state. The backend implements a strict, multi-layered **Spring Security** framework enforcing **Role-Based Access Control (RBAC)** across three distinct tiers: *Admin*, *Manager*, and *Employee*. 
Authentication tokens (JWTs) are completely isolated from client-accessible memory; they are generated by the server and enclosed strictly within **HttpOnly, Secure, and SameSite=Strict cookies**. This architectural barrier physically isolates session data from the JavaScript engine, rendering Cross-Site Scripting (XSS) token extraction impossible.

### 3. Event-Driven Reality & AI Automation (Data Orchestration)
IT environments change second-by-second. Rather than forcing expensive client polling, the backend uses **Server-Sent Events (SSE)** for non-blocking, real-time message alerts and UI updates directly from the server pipeline. Deep background workflows, like massive provisioning or deprecation queues, are processed off the main HTTP thread through **Apache Kafka** event streams.
Finally, rather than static text documentation, an internal **AI Chatbot powered by Retrieval-Augmented Generation (RAG)** allows admins to chat directly with their infrastructure metadata. Utilizing **Model Context Protocol (MCP)**, vector embeddings, and an autonomous **Agent-to-Agent framework**, the AI can orchestrate, analyze, and troubleshoot assets based on raw system telemetry.

## 🛠️ Complete Enterprise Tech Stack

### Frontend Architecture
*   **Core UI:** React.js (v18+), React Lazy (Code-splitting & Asynchronous Bundling)
*   **State & Caching:** Redux Toolkit, React Query (TanStack)
*   **Performance Optimization:** React Window (Virtualization), Memoization UI Primitives
*   **Design & Layout:** Bootstrap (Highly modularized, custom reusable layout components like Cards and Inputs)
*   **Data Layout:** Advanced Client-Side Multi-Parameter Filtering, Server-Driven Dynamic Pagination

### Backend Architecture
*   **Core Runtime:** Java, Spring Boot Framework
*   **Data Access Layer:** Spring Data JPA, Hibernate ORM
*   **Database:** PostgreSQL (Optimized relational schema with indexing on asset UUIDs)
*   **Messaging & Streams:** Apache Kafka (Asynchronous event broker), Server-Sent Events (SSE)
*   **Security Architecture:** Spring Security, JWT (Stateless Tokenization), Cookie-Based Authorization

### AI & LLMOps Engine
*   **Core AI Layer:** Retrieval-Augmented Generation (RAG) Architecture
*   **Data Transformation:** High-Dimensional Vector Embeddings
*   **Protocol & Workflows:** Model Context Protocol (MCP), Multi-Agent Autonomy (Agent-to-Agent communication)
*   **Lifecycle Management:** LLMOps pipeline monitoring model drift and context injection

## ✨ System Architecture & Domain Rules

### Layered Infrastructure Pattern
The platform strictly maintains clean code boundaries via a strict **Four-Tier Architecture**:
1.  **Presentation/UI Layer:** Custom reusable React design paradigms with client/server schema validation.
2.  **Controller Layer:** REST API endpoints handling HTTP serialization, mapping, and entry-point validation.
3.  **Service/Business Layer:** Core domain algorithms, Kafka event triggers, transaction boundaries, and access evaluations.
4.  **Data Access Layer:** JPA repositories orchestrating transactional write/read mappings against PostgreSQL.

### Strict Role-Based Access Matrix

| Feature / Domain Module | Employee Role | Manager Role | Admin Role |
| :--- | :--- | :--- | :--- |
| **Personal Asset Viewing** | ✅ Read Only | ✅ Full View | ✅ Full View |
| **Asset Modification** | ❌ Access Denied | ✅ Write / Update | ✅ Full Control |
| **User Access Provisioning**| ❌ Access Denied | ❌ Access Denied | ✅ Full Control |
| **System Audit Logs** | ❌ Access Denied | ❌ Access Denied | ✅ Full Control |
| **System-Wide Configuration**| ❌ Access Denied | ❌ Access Denied | ✅ Full Control |

## 🛡️ Robust Validation Framework

Data consistency is enforced natively at both entry points before any database interactions occur:
*   **Frontend Validation:** Reactive client-side input interception preventing bad payload packaging before execution.
*   **Backend Validation:** Deep JSR-380/Jakarta Bean Validation constraints protecting API endpoint entities (e.g., `@NotNull`, `@Size`, `@Email`, custom regex matching for IT inventory serials).

## 💻 Local Infrastructure Bootstrap

### Prerequisites
*   Java Development Kit (JDK 21+)
*   Node.js (v20+) & npm
*   PostgreSQL Instance
*   Apache Kafka Instance

### 1. Database Setup
Log into PostgreSQL and initialize the platform catalog:
```sql
CREATE DATABASE it_asset_management;
```

### 2. Backend Environment Variables (`/backend/src/main/resources/application.properties`)
```properties
spring.datasource.url=jdbc:postgresql://localhost:5462/it_asset_management
spring.datasource.username=your_postgres_user
spring.datasource.password=your_secure_password
spring.jpa.hibernate.ddl-auto=update

# Security Configurations
jwt.secret.key=your_ultra_secure_twenty_five_character_long_secret_string
kafka.bootstrap-servers=localhost:9092
```

### 3. Execution Pipeline

Open a shell terminal to execute the core service layer:
```bash
cd backend
./mvnw spring-boot:run
```

Open a second terminal window to launch the client application:
```bash
cd frontend
npm install
npm run dev
```
Navigate to `http://localhost:5173` inside your browser to open the application panel.
