🔐 JWT Authentication — httpOnly Cookie + Refresh Token

JWT is not stored in sessionStorage or localStorage. It is stored in a httpOnly cookie set by the server — JavaScript cannot read it, making it safe from XSS attacks.

❌ Why NOT sessionStorage

  • JavaScript can read sessionStorage → XSS attack steals token
  • Must manually attach token in every Axios request header
  • Tab close = token gone = user must re-login
  • No refresh token support → short-lived = bad UX
  • Attacker injects script → reads token → full account takeover

✅ Why httpOnly Cookie

  • JavaScript cannot read httpOnly cookies — XSS safe
  • Browser sends cookie automatically on every request
  • No manual token attachment needed in Axios
  • Refresh token in separate httpOnly cookie — silent re-auth
  • SameSite=Strict prevents CSRF attacks

Refresh Token Flow (Silent Re-auth)

Access token expires (15min)
→
API returns 401
→
Axios interceptor catches 401
→
POST /api/v1/auth/refresh (sends refresh_token cookie)
→
New access_token cookie set
→
Original request retried automatically

Spring Boot — Set httpOnly Cookie

// AuthService.java — on successful login:
ResponseCookie accessCookie = ResponseCookie.from("access_token", jwtToken)
    .httpOnly(true)       // JS cannot read
    .secure(true)         // HTTPS only
    .path("/")
    .maxAge(15 * 60)      // 15 minutes
    .sameSite("Strict")   // CSRF protection
    .build();

ResponseCookie refreshCookie = ResponseCookie.from("refresh_token", refreshToken)
    .httpOnly(true)
    .secure(true)
    .path("/api/v1/auth/refresh")  // only sent to refresh endpoint
    .maxAge(7 * 24 * 60 * 60)       // 7 days
    .sameSite("Strict")
    .build();

response.addHeader(HttpHeaders.SET_COOKIE, accessCookie.toString());
response.addHeader(HttpHeaders.SET_COOKIE, refreshCookie.toString());

Frontend — Axios Config (no manual token needed)

// axiosInstance.js
const api = axios.create({
  baseURL: '/api/v1',
  withCredentials: true,   // browser auto-sends httpOnly cookie
});

// Response interceptor — silent token refresh on 401
api.interceptors.response.use(
  res => res,
  async err => {
    if (err.response?.status === 401 && !err.config._retry) {
      err.config._retry = true;
      await api.post('/auth/refresh');  // refresh_token cookie sent automatically
      return api(err.config);           // retry original request
    }
    return Promise.reject(err);
  }
);

🔒 Security Summary

  • XSS Protection — httpOnly cookie cannot be read by any JavaScript
  • CSRF Protection — SameSite=Strict blocks cross-site request forgery
  • Short-lived access token — 15 minutes; limits damage if intercepted
  • Long-lived refresh token — 7 days, path-restricted to /auth/refresh only
  • Logout — server clears both cookies (maxAge=0)
  • Secure flag — cookies only sent over HTTPS in production

🔌 MCP — Model Context Protocol

MCP is a standard protocol that lets AI models (like Claude) connect to your IT Asset Management System's tools and data sources. The AI can call your actual Spring Boot APIs as tools.

  • What it does: Exposes your Spring Boot API endpoints as callable tools for an AI assistant
  • Admin types: "Which laptops have warranty expiring this month?" → AI calls GET /api/v1/assets?status=ACTIVE and filters by warrantyExpiry
  • Admin types: "Assign asset #42 to John" → AI calls PUT /api/v1/assets/42/assign
  • AI reads audit logs, checks asset status, creates maintenance requests — all via MCP tools

📚 RAG — Retrieval Augmented Generation

RAG combines a vector database with an LLM. Instead of the AI guessing answers, it first retrieves relevant documents from your system, then generates an accurate response based on that context.

What gets stored in vector DB:

  • Asset manuals and user guides (Dell, HP, Cisco PDFs)
  • Maintenance history logs per asset
  • Company IT policies and procurement rules
  • Past audit log entries (for pattern matching)
  • Asset specifications and purchase records

Example RAG queries in IT Asset:

  • "How do I factory reset a Dell XPS 15?" → retrieves Dell manual chunk
  • "Which assets had similar issues last quarter?" → semantic search on maintenance logs
  • "What is our policy for retiring Laptops?" → retrieves IT policy document
  • "Show me assets like the ones that failed in Feb" → similarity search
// RAG Pipeline for IT Asset Management
// Step 1: Embed and store asset documents
POST /api/v1/ai/embed
{ "content": "Dell XPS 15 manual chapter 3...", "assetType": "Laptop" }
// → generates embedding vector → stored in pgvector

// Step 2: User asks question via ChatWidget
"How do I reset my Dell laptop?"
// → embed question → vector similarity search in pgvector
// → retrieve top 3 relevant manual chunks
// → send chunks + question to LLM → grounded answer returned

🗃️ Vector Database — pgvector (PostgreSQL Extension)

Since your project already uses PostgreSQL, pgvector adds vector storage directly — no separate vector DB service needed. Stores embedding vectors for semantic search.

Setup

-- Enable pgvector extension
CREATE EXTENSION vector;

-- Asset embeddings table
CREATE TABLE asset_embeddings (
  id          BIGSERIAL PRIMARY KEY,
  asset_id    BIGINT REFERENCES assets(id),
  content     TEXT,
  embedding   vector(1536),  -- OpenAI ada-002
  source_type VARCHAR(50)  -- MANUAL/POLICY/LOG
);

-- IVFFlat index for fast similarity search
CREATE INDEX ON asset_embeddings
  USING ivfflat (embedding vector_cosine_ops)
  WITH (lists = 100);

Semantic Search Query

-- Find top 5 most similar documents
SELECT content, asset_id,
  1 - (embedding <=> '[0.12, 0.45, ...]'::vector)
  AS similarity
FROM asset_embeddings
ORDER BY embedding <=>
  '[0.12, 0.45, ...]'::vector
LIMIT 5;
  • Cosine similarity search
  • Searches by meaning not keywords
  • Stays inside your PostgreSQL DB
  • No Pinecone/Weaviate needed

⚙️ LLMOps — LLM Operations for IT Asset Management

LLMOps is the practice of managing, monitoring, and maintaining LLM-powered features in production — like DevOps but for AI models. Applied to the ChatWidget AI assistant in this project.

📊 Monitoring

  • Track every prompt sent via ChatWidget
  • Log response latency per query
  • Monitor token usage per admin session
  • Alert if LLM response time exceeds 3s
  • Log failed/hallucinated responses

🔄 Versioning & Prompt Management

  • System prompt versioned in database
  • A/B test different prompt templates
  • Roll back prompt if response quality drops
  • Track which prompt version gave best answers
  • Store prompt + response pairs for evaluation

✅ Evaluation & Quality

  • Admin thumbs up/down on ChatWidget responses
  • Automated eval: answer relevance score
  • Faithfulness check — does answer match retrieved docs
  • Periodic re-evaluation on golden test set
  • Drift detection — model behavior changes over time

🔁 OLMPs — Online Learning Model Pipelines

OLMPs keep AI models improving continuously as new data comes in — rather than training once and freezing. Applied to the predictive maintenance and asset failure prediction features.

📈 Predictive Maintenance Pipeline

  • Model trained on historical maintenance logs
  • Predicts: which assets are likely to need maintenance in next 30 days
  • New maintenance records → model retrains nightly
  • Spring Boot @Scheduled triggers pipeline at 3 AM
  • Model output stored in asset_predictions table
  • Lifecycle page shows "⚠ Likely maintenance soon" badge

⚡ Online Learning Flow

1
New Event

Asset marked MAINTENANCE → new training sample available

2
Feature Extraction

Age, type, purchase price, last maintenance date → feature vector

3
Incremental Update

Model updated with new sample without full retraining

4
Prediction Refresh

All active assets re-scored → Lifecycle page updated

👥 MANAGER Role — Implementation Details

Manager is a middle tier between EMPLOYEE and ADMIN. A manager can only see and act on data belonging to their direct reports, enforced at the service layer.

How Team Membership Works

Option used: managerId FK on User

  • Each User has a nullable manager_id column (FK → users.id)
  • Manager sees all users where manager_id = manager.id
  • One manager can have multiple employees across branches
  • Employees without a manager_id have no manager (e.g. CEO, ADMIN)
-- Database
ALTER TABLE users ADD COLUMN manager_id BIGINT REFERENCES users(id);
CREATE INDEX idx_users_manager_id ON users(manager_id);

-- Assign employees to manager (id=5)
UPDATE users SET manager_id = 5 WHERE id IN (2, 3, 4);

Security Guard in ManagerService

// Before approve/reject — verify ownership
private void assertOwnsRequest(User manager, AssetRequest request) {
    boolean isTeamMember = getTeamMembers(manager)
        .stream()
        .anyMatch(u -> u.getId()
            .equals(request.getUser().getId()));
    if (!isTeamMember) {
        throw new UnauthorizedException(
            "Not your team member");
    }
}

🗄️ Database Design

-- pgvector extension for RAG + semantic search
CREATE EXTENSION vector;

-- Asset embeddings (RAG vector store)
CREATE TABLE asset_embeddings (
  id          BIGSERIAL PRIMARY KEY,
  asset_id    BIGINT REFERENCES assets(id),
  content     TEXT,
  embedding   vector(1536),
  source_type VARCHAR(50)   -- MANUAL / POLICY / LOG
);
CREATE INDEX ON asset_embeddings USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);

-- Refresh token store
CREATE TABLE refresh_tokens (
  id          BIGSERIAL PRIMARY KEY,
  user_id     BIGINT REFERENCES users(id),
  token       TEXT UNIQUE NOT NULL,
  expiry      TIMESTAMP NOT NULL,
  revoked     BOOLEAN DEFAULT FALSE
);

-- OLMP predictions
CREATE TABLE asset_predictions (
  id                   BIGSERIAL PRIMARY KEY,
  asset_id             BIGINT REFERENCES assets(id),
  maintenance_score    FLOAT,   -- 0.0 to 1.0
  predicted_at         TIMESTAMP,
  model_version        VARCHAR(20)
);

-- Performance indexes
CREATE INDEX idx_assets_status       ON assets(status);
CREATE INDEX idx_assets_warranty      ON assets(warranty_expiry);
CREATE INDEX idx_users_active         ON users(active);
CREATE INDEX idx_audit_logs_action    ON audit_logs(action);
CREATE INDEX idx_audit_logs_timestamp ON audit_logs(timestamp);

-- Full-text search
ALTER TABLE assets ADD COLUMN fts_vector tsvector
  GENERATED ALWAYS AS (to_tsvector('english', coalesce(name,'') || ' ' || coalesce(description,''))) STORED;
CREATE INDEX idx_assets_fts ON assets USING gin(fts_vector);

🗺️ How to read the treemap

🔴 Large box = big package

The bigger the rectangle the more KB it adds to your bundle. Find the biggest boxes first.

🟡 Common offenders

moment.js → replace with date-fns
lodash → import only what you need
@mui/icons → import individual icons

🟢 Good fix — lazy load

Split large pages into separate chunks so they only load when the user navigates to them.

Fix large bundle — React.lazy + Suspense (code splitting)

// Before — all pages load upfront (large initial bundle)
import AdminDashboard from './pages/AdminDashboard';
import AssetLifecycle from './pages/AssetLifecycle';
import AuditLogs      from './pages/AuditLogs';

// After — each page loads only when user navigates to it
const AdminDashboard = React.lazy(() => import('./pages/AdminDashboard'));
const AssetLifecycle = React.lazy(() => import('./pages/AssetLifecycle'));
const AuditLogs      = React.lazy(() => import('./pages/AuditLogs'));

// Wrap routes in Suspense
<Suspense fallback={<LoadingSkeleton/>}>
  <Routes>...</Routes>
</Suspense>

🛠️ Step 3 — Fix Re-render Issues

Fix 1 — React.memo (stops re-render when props didn't change)

// Before — re-renders every time parent re-renders
export default function AssetCard({ asset, onEdit }) {
  return <div>{asset.name}</div>;
}

// After — only re-renders if asset or onEdit prop changed
const AssetCard = React.memo(function AssetCard({ asset, onEdit }) {
  return <div>{asset.name}</div>;
});
export default AssetCard;

// Applied in this project: AssetCard.jsx ✅

Fix 2 — useCallback (stops function props looking "new" every render)

// Before — new function created every render → React.memo on child won't help
function AssetList() {
  const handleEdit = (asset) => setEditAsset(asset); // new fn every render
  return assets.map(a => <AssetCard onEdit={handleEdit} />);
}

// After — same function reference, React.memo works correctly
function AssetList() {
  const handleEdit = useCallback((asset) => {
    setEditAsset(asset);
  }, []); // only recreates if dependencies change
  return assets.map(a => <AssetCard onEdit={handleEdit} />);
}

Fix 3 — useMemo (stops heavy calculations running every render)

// Before — recalculates total value on every keystroke in search box
const totalValue = assets.reduce((sum, a) => sum + a.purchaseCost, 0);

// After — only recalculates when assets array changes
const totalValue = useMemo(() =>
  assets.reduce((sum, a) => sum + a.purchaseCost, 0),
[assets]);

// Also used for branchUserCount map in BranchManagement.jsx ✅
const branchUserCount = useMemo(() => {
  const map = {};
  (usersData?.content || []).forEach(u => {
    if (u.branchId) map[u.branchId] = (map[u.branchId] || 0) + 1;
  });
  return map;
}, [usersData]);

Fix 4 — Redux useSelector (stops new object reference causing re-render)

// Bad — returns new object every render → always re-renders
const { user, role } = useSelector(state => ({
  user: state.auth.user,
  role: state.auth.role,
}));

// Good — separate selectors, only re-renders if that value changes
const user = useSelector(state => state.auth.user);
const role = useSelector(state => state.auth.role);

// Best — createSelector (reselect) for computed values
import { createSelector } from '@reduxjs/toolkit';
const selectActiveAssets = createSelector(
  state => state.assets.list,
  list => list.filter(a => a.status === 'ACTIVE') // memoized
);

Fix 5 — Virtualization (long lists — only render visible items)

// Bad — renders ALL 1000 assets in DOM at once
assets.map(a => <AssetCard key={a.id} asset={a} />)

// Good — only renders ~10 visible items at a time (react-window)
import { FixedSizeList } from 'react-window';

<FixedSizeList
  height={500}
  itemCount={assets.length}
  itemSize={80}
>
  {({ index, style }) => (
    <AssetCard style={style} asset={assets[index]} />
  )}
</FixedSizeList>
